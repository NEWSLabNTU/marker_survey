# Phase 1: the marker map file

## Goal

One file per site that the survey writes, a person can read and fix by
hand, and the localizer reads directly. The two source implementations used
two files and conversion steps (a course file turned into a lanelet2 map and
localizer parameters; a plain list of x, y, z, yaw). Every conversion step is
a place where a site falls out of date, so there is none: robots read
`marker_map.yaml` as it is.

## Choices, by what the person editing it needs

| Question | Choice | Why |
|---|---|---|
| Units | metres; angles in degrees, with `_deg` in the key | people measure and think in degrees; the key says the unit, so nobody guesses |
| Orientation | relative to the marker's mounting (`mount: wall`, `ceiling`, `floor`), so a well-mounted marker has small numbers | a ceiling marker facing down then reads `rotation_deg: 30`, not a roll of 180 and a yaw of -150 |
| One line per marker | flow style, aligned columns, comments kept | a site with 40 markers stays one screen; a comment can say "above the coffee machine" |
| Uncertainty and view counts | in `survey_report.yaml`, not in the map | the map stays clean; the report is regenerated by every solve |
| Sizes | a default `marker_size`, per-marker `size` where different | sites mix sheet sizes |
| Validation | a loader that names the line and the field on every error | "marker 12: rotation_deg missing" rather than a stack trace |

## Format, version 1

```yaml
# Ceiling markers of the warehouse, surveyed 2026-11-03.
version: 1
frame_id: map                 # the frame the robot's map uses
dictionary: tag36h11          # printed family
marker_size: 0.45             # [m] edge of the black square, measured
mount: ceiling                # default for every marker below
markers:
  - {id: 0,  x: -4.000, y:  1.500, z: 3.012, rotation_deg:   0.0}
  - {id: 1,  x: -1.500, y:  1.500, z: 2.998, rotation_deg:  45.8}
  - {id: 7,  x:  3.000, y: -2.000, z: 3.204, rotation_deg:  91.7, tilt_x_deg: 1.2}   # under the duct
  - {id: 12, x:  0.300, y:  3.000, z: 3.005, rotation_deg:  17.2, size: 0.30}
```

```yaml
# Boards around the test course.
version: 1
frame_id: map
dictionary: DICT_5X5_1000
marker_size: 0.38
mount: wall
markers:
  - {id: 10, x: 0.000, y: 0.000, z: 0.250, facing_deg:   0.0}               # origin
  - {id: 11, x: 6.800, y: 1.950, z: 0.248, facing_deg: 180.0, lean_deg: 2.1}
```

Fields per mount:

| Mount | Reference pose (all angles zero) | Angles |
|---|---|---|
| `wall` | upright, facing +x, top up | `facing_deg` (about z), `lean_deg` (top leaning back), `turn_deg` (in its own plane) |
| `ceiling` | facing down, top towards +x | `rotation_deg` (about z), `tilt_x_deg`, `tilt_y_deg` (small) |
| `floor` | facing up, top towards +x | `rotation_deg`, `tilt_x_deg`, `tilt_y_deg` |

Each maps to one rotation matrix in `core/marker_map.py`; the localizer and
the survey use only the matrix. Missing angles are zero.

## Tasks

- [ ] `core/marker_map.py`: load, validate (errors with line and field),
      write (aligned flow style, comments round-trip with ruamel.yaml), the
      mount conventions and their matrices
- [ ] JSON Schema for editors (`marker_map.schema.json`)
- [ ] `marker_map_check` tool: loads, validates, prints a top-down plot
- [ ] Importers for the two source formats (one-off migration of existing
      sites; not used at run time)
- [ ] Unit tests: each mount's reference orientation, round trip of values
      and comments, error messages

## Done when

The two existing sites (a wall course of 11 boards, an office of 9 ceiling
markers) import, write and load back to the same marker poses within 1e-6,
with comments kept.
